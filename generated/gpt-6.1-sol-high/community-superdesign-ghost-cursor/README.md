# Ghost Cursor

Design ID: `community-superdesign-ghost-cursor`

A working React 18 + TypeScript + Three.js integration of the component in `PROMPT.md`. The page preserves the supplied centered title, instruction, dark background, subtle purple-to-blue gradient, responsive typography, and procedural lavender smoke trail. No page screenshot is used in the implementation.

The demo uses the requested values: color `#B19EEF`, brightness `1.2`, edge intensity `0`, trail length `20`, inertia `0.4`, grain `0.05`, bloom strength `0.5`, bloom radius `0.7`, bloom threshold `0`, and fade delay/duration `200`/`1000` ms. Text uses the system sans-serif stack implied by the supplied utility classes. There are no external font, image, or runtime CDN requests.

## Build and run

With Node 22/npm installed:

```sh
npm ci
npm run build
npm run dev
```

Open `/motionsites-results/community-superdesign-ghost-cursor/` on the dev server. The production build is in `dist/`, with the same absolute base configured in `vite.config.ts`. Serve or mount that directory at the configured URL prefix.

This host uses the existing Docker image for Node and Chromium:

```sh
docker run --rm -u 1000:1000 -e HOME=/tmp -v "$PWD:/work" -w /work --entrypoint sh louislam/uptime-kuma:2 -c 'npm ci && npm run build'
```

The dependency lockfile is included. `node_modules/` is ignored and is not a deliverable.

## Component

Import `GhostCursor` from `src/Component.tsx` and place it inside a positioned container. The overlay ignores pointer events and follows input on its parent. The original configurable props remain available, including color, brightness, trail length, inertia, grain, bloom, edge intensity, blend mode, pixel budget, fade timings, style, and z-index.

Integration corrections include idle fade while the pointer remains inside the page, touch release/cancel handling, a nonzero shader smoothstep radius at zero opacity, screen blending on the overlay stacking layer, and post-processing resource disposal. Animation stops after fading and restarts on input. ResizeObserver updates the rendering resolution with the original 0.5 device-pixel-ratio cap.

## Browser verification

```sh
docker run --rm -u 1000:1000 -e HOME=/tmp -v "$PWD:/work" -w /work --entrypoint node louislam/uptime-kuma:2 scripts/browser-check.cjs
```

The check serves the actual production files at the required subpath and uses the image's `playwright-core` and Chromium. It checks desktop 1440×1000 and touch-enabled mobile 390×844, expected text, canvas presence, horizontal/vertical overflow, pointer and touch input, visible active-versus-faded output, reactivation, resize, console errors, page errors, and failed HTTP responses.

Required screenshots are `screenshots/desktop.png` and `screenshots/mobile.png`. Additional idle/faded/restarted screenshots provide comparison evidence. Continuous pointer events keep the trail active during screenshot capture because the software WebGL renderer can take longer than the specified fade duration. The test also dispatches real browser mouse and touch input. Machine-readable browser results are stored in `screenshots/browser-checks.json`.

## Assets and limitations

The optional reference `/home/opc/motionsites/assets/previews/community-superdesign-ghost-cursor.webp` was absent. Implementation therefore follows the supplied source and layout; no reference-image extraction was needed. The visual effect is generated by the original Three.js shaders, bloom, and grain rather than bitmap assets.

Production compilation includes TypeScript checking. Vite reports a nonfatal bundle warning because the app includes Three.js and its post-processing modules (approximately 622 kB minified / 168 kB gzip). Browser verification uses Chromium with SwiftShader software WebGL; it establishes functionality and screenshot output, not hardware GPU frame-rate performance. A WebGL-capable browser is required. Nothing was deployed or pushed.
